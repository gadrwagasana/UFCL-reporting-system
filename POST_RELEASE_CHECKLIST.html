A Git Tag Creation

A-01. Confirm working tree is clean
No uncommitted changes should be present before tagging
git status
# Expected: nothing to commit, working tree clean
# If files are modified: commit them first with a brief message
A-02. Create annotated release tag
Use annotated tag (not lightweight) so the tagger and date are recorded
git tag -a v1.0.0 -m "UFCL Mobile v1.0.0 — Initial production release

- 15 production modules across 12 departments
- Offline-first with Zustand queue + sync
- JWT auth, SecureStore, workshop isolation
- OTA auto-update via HTTPS
- 92/100 production readiness score"
A-03. Verify tag was created
git tag -l "v1.0.0"      # should print: v1.0.0
git show v1.0.0          # should show tag metadata and commit
A-04. Push tag to remote
Do not push until production approval is confirmed — tag is permanent
git push origin v1.0.0
Do NOT use git push --tags — this pushes all local tags including any unreviewed ones. Push only v1.0.0 explicitly.
A-05. Verify tag is visible on GitHub
GitHub → Releases → Tags tab should show v1.0.0

B GitHub Release Publication

B-01. Trigger the release workflow
Go to GitHub → Actions → "Mobile — Build & Release APK" → Run workflow
  • Version name override: 1.0.0
  • Force mandatory update: false (first release — no previous version to update from)
  • Release notes: Initial production release,15 modules,12 departments,OTA auto-update
Alternatively: push a commit touching mobile/** to master to auto-trigger. The workflow reads version_name from mobile/package.json when no override is given.
B-02. Monitor the CI run (~8 minutes)
All 14 steps should pass. Watch for failures in step 5 (keystore decode), step 8 (Gradle build), step 13 (SSH deploy)
B-03. Verify GitHub Release was created
  • GitHub → Releases should show "UFCL Mobile v1.0.0"
  • Release assets: UFCL-production-1.0.0.apk, version.json, apk.sha256, apk.md5
  • Release is marked as "Latest release"
B-04. Update GitHub Release description
Edit the auto-generated description and paste the full GitHub Release text (see below)

C APK Deployment to Production Server

C-01. Confirm APK is on the server (CI deploys automatically)
ssh $DEPLOY_USER@192.168.1.5
ls -lh /opt/ufcl-api/updates/
# Expected:
#   UFCL-production.apk   (signed release APK)
#   version.json          (update metadata)
#   apk.sha256            (checksum)
#   apk.md5               (checksum)
C-02. Verify version.json content
curl -k https://192.168.1.5/version.json | jq .
# Must show:
#   "version": "1.0.0"
#   "apkUrl": "https://192.168.1.5/downloads/UFCL-production.apk"
#   "mandatory": false
C-03. Verify APK download over HTTPS
curl -kI https://192.168.1.5/downloads/UFCL-production.apk
# Expected: HTTP/2 200, content-type: application/vnd.android.package-archive
# content-length: should be > 20 MB
C-04. Cross-check APK SHA-256 against GitHub Release
curl -k https://192.168.1.5/downloads/apk.sha256
# Must match the sha256 shown in the GitHub Release artifacts

D Auto-Update Verification

For v1.0.0 (first release), there is no previous version to update from. These steps verify the update infrastructure is ready for v1.0.1+. Use a debug build with a lower versionCode to simulate an "older" version.
D-01. Install a lower-versionCode build on a test device
Install a dev/debug build that has a versionCode lower than the CI-built v1.0.0
D-02. Open the app and wait ~5 seconds
The update checker fires 3 seconds after launch. Verify the update modal appears.
  • Modal shows: version number, release notes, Update Now and Later buttons
  • "Later" dismisses the modal (non-mandatory update)
D-03. Tap "Update Now" and verify download
  • Progress bar appears
  • Download completes (file size matches server)
  • MD5 check passes silently
  • Install Now button appears
D-04. Tap "Install Now" and complete installation
  • Android installer launches
  • Install completes, app relaunches at v1.0.0
  • No further update modal (already on latest)
D-05. Test resume download (simulate interrupted download)
  • Start download → enable airplane mode mid-download
  • Disable airplane mode → tap Retry
  • Download resumes from where it stopped (HTTP Range request)

E Database Backup Verification

E-01. Run a manual backup immediately after go-live
cd /opt/ufcl-api
PGPASSWORD="$(grep PGPASSWORD .env | cut -d= -f2)" bash tools/backup.sh
# Should log: "====== Backup complete ======"
E-02. Verify backup file was created and is readable
ls -lh /opt/ufcl-backups/daily/
gzip --test /opt/ufcl-backups/daily/db-$(date +%Y-%m-%d).sql.gz
echo $?   # must be 0
E-03. Confirm cron job is active
crontab -l | grep backup
# Expected: 0 2 * * * PGPASSWORD=... /opt/ufcl-api/tools/backup.sh

F Production Monitoring Verification

F-01. Verify all health endpoints
curl -k https://192.168.1.5/api/health | jq '{ok,status,uptime}'
curl -k https://192.168.1.5/api/ready  | jq '{ok,db}'
curl -k -H "Authorization: Bearer $METRICS_TOKEN" \
     https://192.168.1.5/api/metrics | jq '{ok,uptime_seconds,active_sessions}'
F-02. Load monitoring dashboard
Browser: https://192.168.1.5/dashboard.html — enter server URL and METRICS_TOKEN
  • Active sessions counter visible
  • Request rate: 0 (no users yet)
  • Memory usage: < 100 MB (no load yet)
  • Uptime: matches PM2 start time
F-03. Test auto-start after server reboot
sudo reboot
# Wait ~60 seconds after boot, then:
pm2 status                                       # mobile-api: online
curl -k https://192.168.1.5/api/health | jq .ok  # true
curl -k https://192.168.1.5/version.json | jq .version  # "1.0.0"
