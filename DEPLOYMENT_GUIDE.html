0Prerequisites & Secrets

Secret nameValue

KEYSTORE_PASSWORDStore password for the keystore

DEPLOY_SSH_KEYPrivate SSH key for the deploy user on 192.168.1.5

1Server Deployment
STEP 1

Clone repository and install API dependencies

git clone https://github.com/gadrwagasana/UFCL-reporting-system.git /opt/ufcl-api
cd /opt/ufcl-api/mobile-api
npm install --production
STEP 2

Create production .env file

cat > /opt/ufcl-api/.env <<'ENV'
PGHOST=localhost
PGPORT=5432
PGDATABASE=ufcl_production
PGUSER=postgres
PGPASSWORD=your_db_password_here

JWT_SECRET=$(openssl rand -hex 32)

MOBILE_API_PORT=3001
API_BIND_HOST=127.0.0.1
API_BEHIND_PROXY=true
METRICS_TOKEN=$(openssl rand -hex 24)
LOG_DIR=/opt/ufcl-api/logs

UPDATES_DIR=/opt/ufcl-api/updates
ENV
Generate JWT_SECRET and METRICS_TOKEN with openssl rand -hex 32 — do not reuse values from other environments.
STEP 3

Run database migrations

cd /opt/ufcl-api
node db/migrate.js
# Verify: all tables created
psql -U postgres -d ufcl_production -c "\dt" | wc -l
STEP 4

Generate TLS certificate

sudo bash /opt/ufcl-api/tools/ssl-setup.sh
# Output: /etc/ssl/ufcl/server.crt and server.key
# Validity: 10 years (self-signed, SAN = IP:192.168.1.5)
STEP 5

Deploy nginx configuration

sudo cp /opt/ufcl-api/tools/nginx.conf /etc/nginx/sites-available/ufcl-mobile
sudo ln -sf /etc/nginx/sites-available/ufcl-mobile /etc/nginx/sites-enabled/
# Remove default site if present
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
STEP 6

Configure firewall

sudo bash /opt/ufcl-api/tools/firewall-setup.sh
# Resulting policy:
#   ALLOW  22/tcp   SSH
#   ALLOW  80/tcp   HTTP → HTTPS redirect
#   ALLOW  443/tcp  HTTPS (nginx)
#   DENY   3001/tcp Express direct
#   DENY   5432/tcp PostgreSQL direct
STEP 7

Create log and backup directories

mkdir -p /opt/ufcl-api/logs /opt/ufcl-api/updates
mkdir -p /opt/ufcl-backups/{daily,weekly,monthly}
STEP 8

Start API with PM2

cd /opt/ufcl-api/mobile-api
pm2 start ecosystem.config.js --env production
pm2 save
pm2 startup  # follow the printed command to enable auto-start on reboot
STEP 9

Install backup cron jobs

sudo bash /opt/ufcl-api/tools/cron-setup.sh
# Verify:
crontab -l | grep backup   # should print the 02:00 cron line
STEP 10

Verify server is working

# From any machine on the LAN:
curl -k https://192.168.1.5/api/health | jq '{ok,status,uptime}'
curl -k https://192.168.1.5/api/ready  | jq '{ok,db}'

# Confirm Express is NOT reachable directly:
curl http://192.168.1.5:3001/api/health   # must time out or connection refused
Expected: {"ok":true,"status":"healthy","uptime":...} from health endpoint.
2APK Build & Release — GitHub Actions
OPTION A — Tag trigger (recommended for v1.0.0)

Tag the release and push

git tag v1.0.0
git push origin v1.0.0
The workflow triggers on push to master with changes in mobile/**. For a dedicated release tag, trigger manually (Option B) or push a commit that modifies mobile/ then immediately deploy.
OPTION B — Manual workflow dispatch

Trigger release via GitHub UI

  1. Go to GitHub → Actions → Mobile — Build & Release APK
  2. Click Run workflow
  3. Fill in:
    • Version name override: 1.0.0
    • Force mandatory update: false (first release — no previous version to update from)
    • Release notes: Initial production release
  4. Click Run workflow
WHAT THE CI DOES

Automated build steps (14 steps, ~8 minutes)

StepAction
1–4Checkout, Java 17, Node 22, npm ci
5–6Decode keystore from secret; write keystore.properties
7Resolve version: VERSION_NAME from input or package.json; VERSION_CODE = git commit count
8Gradle assembleRelease with APP_PACKAGE_ID=com.ufcl.mobile, EXPO_PUBLIC_API_URL=https://192.168.1.5
9Locate and rename APK to UFCL-production-1.0.0.apk
10Compute SHA-256 and MD5 checksums
11Generate version.json (GitHub CDN URL) and version-server.json (LAN HTTPS URL)
12Create GitHub Release with APK, version.json, checksums attached
13SCP APK + checksums to 192.168.1.5; SSH to write version.json atomically
14Upload artifact (30-day retention)

6Rollback Procedure
API ROLLBACK

Roll back the API to a previous version

cd /opt/ufcl-api
git log --oneline -10                    # identify the target commit
git checkout <commit-hash>
cd mobile-api && npm install --production
pm2 reload ecosystem.config.js --env production
curl -k https://192.168.1.5/api/health | jq .ok
DATABASE ROLLBACK

Restore database from backup

# Drop and recreate (destructive — confirm before running)
psql -U postgres -c "DROP DATABASE IF EXISTS ufcl_production;"
psql -U postgres -c "CREATE DATABASE ufcl_production;"

# Restore
gunzip -c /opt/ufcl-backups/daily/db-2026-06-29.sql.gz \
  | psql -U postgres -d ufcl_production

# Verify row counts
psql -U postgres -d ufcl_production -c "
  SELECT table_name, pg_total_relation_size(table_name::text) AS size
  FROM information_schema.tables
  WHERE table_schema='public' ORDER BY size DESC LIMIT 10;"
Restore operation replaces all data. Confirm with CEO / operations before proceeding.
APK ROLLBACK

Revert the OTA update to a previous APK version

# From the GitHub Release page, download the previous version's APK + checksums
# Then on the server:
cd /opt/ufcl-api/updates
cp UFCL-production.apk UFCL-production.apk.bak    # backup current

# Upload previous APK to server and update version.json:
# Set versionCode to the PREVIOUS version's code so devices see a "downgrade"
# (or set mandatory:true to force re-install)
# Edit version.json manually:
node -e "
  const fs=require('fs');
  const v=JSON.parse(fs.readFileSync('version.json'));
  v.version='0.9.x';     // previous version name
  v.versionCode=NNN;      // previous version code (must be LOWER than current)
  v.mandatory=true;
  fs.writeFileSync('version.json', JSON.stringify(v,null,2));
  console.log('Rolled back version.json to', v.version);
"
Android does not allow installing an older versionCode over a newer one without uninstalling first. To force a rollback, devices must uninstall the app and re-sideload the older APK.
7User Installation — Initial (Sideload)
PREREQUISITES — EACH DEVICE

Install TLS certificate (one-time per device)

  1. On the server: sudo cat /etc/ssl/ufcl/server.crt
  2. Copy server.crt to the Android device (USB or shared folder)
  3. On the device: Settings → Security → Encryption & credentials → Install a certificate → CA certificate
  4. Select server.crt and accept the prompt
  5. The device now trusts the UFCL server's HTTPS certificate
This step is required once per device. Without it, the app can still connect but the update checker may show certificate errors.
STEP A — ENABLE UNKNOWN SOURCES

Allow installation of non-Play Store apps

  1. Settings → Apps → Special app access → Install unknown apps
  2. Select the file manager or browser you will use to open the APK
  3. Toggle Allow from this source ON
  4. After installation, disable this setting again for security
STEP B — INSTALL APK

Install UFCL-production.apk

  1. Download UFCL-production.apk from:
    • Company server: https://192.168.1.5/downloads/UFCL-production.apk
    • Or copy from USB flash drive
    • Or scan the QR code distributed by IT
  2. Tap the downloaded file → Install
  3. Accept permissions prompt
  4. Wait for installation to complete → Open

8User Installation — App Update (OTA)
HOW IT WORKS

Automatic update detection

After a new APK is deployed to the server (via CI), the app checks for updates:

  • 3 seconds after launch
  • Every 4 hours while the app is running
  • When the app returns to foreground after being backgrounded for 10+ minutes

If a new versionCode is found at https://192.168.1.5/version.json, a modal appears.

USER EXPERIENCE

Update modal behaviour

ScenarioBehaviour
Non-mandatory updateModal shows "Update Available". User can tap Update Now or Later. "Later" dismisses until next restart.
Mandatory updateModal shows "Required Update". No dismiss button. User must update.
Download in progressProgress bar shown. Download is resumable if interrupted.
Download completeMD5 checksum verified. Install Now button prompts Android installer.
Checksum mismatchError shown: "File integrity check failed. Please retry."
Server unreachableSilent fail — app opens normally, no error shown.
IT: PUSH A MANDATORY UPDATE

Force-update all devices

  1. Trigger the CI workflow with Force mandatory update: true
  2. All devices currently running the app will show the mandatory modal at next check
  3. Devices not running the app will see the modal at next launch
9Post-Deployment Monitoring

Daily operations checklist

# 1. Check API health
curl -k https://192.168.1.5/api/health | jq .

# 2. Check PM2 status
pm2 status

# 3. Check error log
grep '"level":"error"' /opt/ufcl-api/logs/app-$(date +%Y-%m-%d).log | jq . | head -20

# 4. Confirm backup ran
tail -5 /opt/ufcl-backups/backup.log

# 5. Check disk
df -h / /opt
