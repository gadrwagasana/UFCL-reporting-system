3. Integrity Verification

After each backup file is written, backup.sh runs gzip --test to verify the compressed file is not corrupt.

# From backup.sh (verified in source):
gzip --test "$DAILY_DIR/db-${TODAY}.sql.gz"
if [ $? -ne 0 ]; then
    echo "CRITICAL: backup integrity check FAILED — $DAILY_DIR/db-${TODAY}.sql.gz"
    exit 1
fi

A failed integrity check exits with code 1 and logs CRITICAL — the cron output is captured in /opt/ufcl-backups/backup.log.

4. Retention and Rotation

Old files are removed via find ... -mtime +N -delete after each backup run.

5. Restore Procedure

Database restore

# Step 1: Stop the API to prevent writes during restore
pm2 stop mobile-api

# Step 2: Drop and recreate the database
psql -U postgres -c "DROP DATABASE IF EXISTS ufcl_production;"
psql -U postgres -c "CREATE DATABASE ufcl_production;"

# Step 3: Restore from backup
gunzip -c /opt/ufcl-backups/daily/db-YYYY-MM-DD.sql.gz \
  | psql -U postgres -d ufcl_production

# Step 4: Verify row counts
psql -U postgres -d ufcl_production -c "
  SELECT 'harvest_entries' AS tbl, COUNT(*) FROM harvest_entries
  UNION ALL
  SELECT 'deliveries',              COUNT(*) FROM deliveries
  UNION ALL
  SELECT 'fuel_vehicle',            COUNT(*) FROM fuel_vehicle
  UNION ALL
  SELECT 'audit_log',               COUNT(*) FROM audit_log;
"

# Step 5: Restart the API
pm2 start ecosystem.config.js --env production
curl -k https://192.168.1.5/api/ready | jq .

Config restore

tar -xzf /opt/ufcl-backups/daily/config-YYYY-MM-DD.tar.gz -C /
# Restores .env and nginx config to their original paths
nginx -t && systemctl reload nginx

APK/version.json restore

tar -xzf /opt/ufcl-backups/daily/updates-YYYY-MM-DD.tar.gz -C /opt/ufcl-api/
# Restores UFCL-production.apk, version.json, apk.sha256, apk.md5
