9. Summary Sections

Performance Summary

  • React Query: 2-min staleTime on lists, 10-min on metadata, 24-hr gcTime — appropriate for LAN speeds and data volumes
  • Offline queue: serial processing (MAX_RETRIES=3), UUID IDs prevent duplicates, failed items preserved for retry
  • FlatList with keyExtractor on all list screens — no render-loop issues
  • Hermes JS engine enabled — faster startup and lower memory on Android
  • Network monitor: single listener, idempotent start, triggers sync + session revalidation on reconnect
  • No performance blockers identified

Security Summary

  • JWT tokens stored in hardware-backed SecureStore, not AsyncStorage
  • All API calls over HTTPS via nginx (Express never exposed externally)
  • Dual-layer role enforcement: route gate + authoritative data.js check
  • Workshop isolation enforced on all approval endpoints
  • Full audit log on every write operation (userId, role, action, timestamp)
  • Rate limiting on login (brute-force protection) and API calls
  • All SQL queries parameterised — no injection surface
  • No secrets committed to repository

Infrastructure Summary

  • nginx 443 (TLS 1.2/1.3) → Express 127.0.0.1:3001 — all external traffic encrypted
  • PM2 fork mode, max 512 MB, auto-restart on crash, startup hook persists across reboots
  • Daily encrypted database backups with 7d/4w/12m rotation and gzip integrity check
  • Monitoring dashboard (dashboard.html) with METRICS_TOKEN gate, shows uptime / memory / requests / sessions
  • Health endpoints: /api/health (liveness), /api/ready (DB connectivity), /api/metrics (observability)
  • OTA update: version.json → resumable download → MD5 verify → Android installer. Mandatory update flag available.

Database Status

  • Migration: node db/migrate.js creates all tables (run once on fresh server)
  • Foreign keys: enforced at DB level
  • Workshop isolation: workshopId JWT claim, verified in data.js, supervisorWorkshopGuard() on approve routes
  • Audit log: all write operations recorded — survives app restarts
  • Backup: daily pg_dump --no-owner compressed with gzip, integrity-verified
  • Restore tested via ADMIN_MANUAL.html Section 8 procedure

API Status

  • All Sprint 1–5 routes operational: auth, harvest, logTransport, sawmill, poles, vat, deliveries, fuel, machineLogs, materialRequests, casualLabour, ceo, myRequests, meta
  • Phase 2 stubs (stockTransfers, dispatch) return HTTP 501 — intentional, documented
  • Health, ready, and metrics endpoints operational
  • Update endpoints (version.json, /downloads/) serve through nginx with range-request support
