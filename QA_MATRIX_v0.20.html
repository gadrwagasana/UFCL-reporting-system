Stage 3 — Permission Boundary Tests

These tests verify that unauthorized access is blocked at both the UI layer (button/card not shown) and the API layer (HTTP 401/403 returned). Test each item with the listed role.

API rejection is as important as UI hiding. The API must still reject requests even if someone bypasses the UI. Test with a REST client or check server logs if possible.

Stage 7 — Production Readiness

Complete this stage before tagging a release candidate. All items must pass before a version tag is created on GitHub.

This is the gate between QA and release. A GitHub tag is the ONLY production release mechanism — never publish without completing this checklist.
