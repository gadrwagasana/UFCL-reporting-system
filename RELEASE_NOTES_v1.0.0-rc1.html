Breaking Changes

This is the initial production release of the mobile application. There is no prior mobile version to upgrade from, so there are no breaking changes from a mobile perspective.

The desktop application (electron/) is unaffected by this release. The mobile API (mobile-api/) runs as a separate service and does not modify any existing desktop API routes or database tables used exclusively by the desktop.

If upgrading the shared database schema (via npm run migrate), the desktop application should be tested after migration to confirm no regressions in its data layer.

Rollback Procedure

Before any release deployment: take a full database backup. Rollback is only safe if a pre-deployment backup exists.

Step 1 — Stop the mobile API

pm2 stop mobile-api

Step 2 — Restore the pre-deployment database backup

pg_restore -U ufcl -d ufcl_db /path/to/backup_pre_rc1.dump

If migrations were not run (i.e. the database schema is unchanged), this step may be skipped — the API will still function with the previous version's code.

Step 3 — Check out the previous release tag

git checkout v0.20-stable     # or the previous known-good tag
npm install --prefix mobile-api
pm2 restart mobile-api

Step 4 — Redistribute the previous APK

Reinstall the previous APK on affected devices. Because the app communicates exclusively via the mobile API, reverting the server is sufficient to restore prior functionality without touching client devices, provided the API contract has not changed.

Step 5 — Verify

pm2 status
curl https://your-server/api/health
