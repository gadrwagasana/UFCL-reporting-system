2. Mobile App — Design Analysis

Startup path

  • Splash screen: Renders natively before JS bundle loads — no blank screen
  • Session restore: SecureStore.getItemAsync is async but fast (hardware keystore read)
  • Token revalidation: /api/auth/me fires once on startup; React Query caches result for staleTime=5min in App.tsx
  • Navigator mount: Lazy-loaded stacks — only the initial tab's screen is rendered on load

List rendering

  • All lists use FlatList with keyExtractor — virtual rendering, off-screen items not mounted
  • Pull-to-refresh via React Query refetch()
  • Empty state and loading skeleton rendered before data arrives
  • No nested FlatList structures

Network efficiency

  • React Query: staleTime=2min on list queries, 10min on meta (vehicles, users) — avoids redundant requests
  • gcTime=24h — cached data survives background kills; displayed instantly on next foreground
  • Single Axios instance with baseURL=https://192.168.1.5 — no DNS lookup on each request
  • Bearer token attached via Axios interceptor — not re-read from SecureStore per request

Offline queue efficiency

  • Serial processing (one item at a time) — avoids DB connection exhaustion on sync
  • UUID v4 IDs generated client-side — server does INSERT ... ON CONFLICT DO NOTHING (idempotent)
  • MAX_RETRIES=3 — prevents infinite retry loop on permanently failed items
  • Zustand store persisted to AsyncStorage — survives process kill

3. Backend API — Design Analysis

Database connection pool

  • max: 20 connections — adequate for 60–100 concurrent users (queries are short; connections returned immediately after query)
  • idleTimeoutMillis: 30000 — idle connections released after 30s, reducing PostgreSQL resource usage
  • connectionTimeoutMillis: 5000 — requests fail fast (5s) rather than hanging indefinitely

Query complexity

  • All queries are single-table or simple 2-table JOINs — no expensive multi-join aggregations
  • Indexes on primary keys and foreign keys (PostgreSQL default)
  • All list endpoints include LIMIT clauses — no unbounded result sets
  • Parameterised queries reuse prepared statement plans

PM2 process model

  • Fork mode (single process) — appropriate for I/O-bound Express server; cluster mode not needed at this scale
  • max_memory_restart: 512M — Node.js heap limit; typical idle usage < 100 MB
  • Graceful shutdown on SIGTERM — in-flight requests complete before process exits

nginx tuning

  • proxy_read_timeout 300s on /downloads/ — allows large APK download without timeout
  • proxy_read_timeout 30s on API routes — fast fail for hung upstream
  • gzip enabled — reduces API response size ~60–70% for JSON payloads
  • HTTP Range requests supported on APK download — enables resumable OTA
