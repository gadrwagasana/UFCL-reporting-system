Request flow

Android device → WiFi → nginx :443 (TLS) → Express :3001 → PostgreSQL
The Express API (port 3001) must NEVER be directly reachable from devices. All traffic must go through Nginx on port 443. UFW blocks port 3001 externally. Verify: curl http://192.168.1.5:3001/api/health must fail from any device.

2. User Management

Creating a new user

# Connect to the database
psql -U postgres -d ufcl_production

# Insert user (replace values, never reuse passwords)
INSERT INTO users (username, password_hash, role, workshop_id, active)
VALUES (
  'jane.sawmill',
  crypt('TemporaryPass123', gen_salt('bf', 12)),
  'sawmill-leader',
  NULL,
  true
);
Always use crypt() with bcrypt (bf). Never store plain-text passwords. The pgcrypto extension must be enabled: CREATE EXTENSION IF NOT EXISTS pgcrypto;

Disabling a user (e.g. staff departure)

UPDATE users SET active = false WHERE username = 'jane.sawmill';
-- Do NOT delete users — audit_log references their user_id

Resetting a password

UPDATE users
SET password_hash = crypt('NewTemp999', gen_salt('bf', 12))
WHERE username = 'jane.sawmill';
-- Tell the user to change it on first login via Profile → Change Password

Role assignments

See Section 8 (Role Reference) for the full list of valid role values.

Workshop assignment

For roles that are workshop-restricted (harvesting-supervisor, supervisor), the workshop_id column must be set to the correct workshop ID. Check valid IDs:

SELECT id, name FROM workshops ORDER BY id;
Workshop isolation is a security boundary. A supervisor assigned to Workshop A must NEVER be able to see Workshop B data. Always verify workshop_id is correct before activating a supervisor account.

3. Server Operations

PM2 — API process management

pm2 status                        # check API is online
pm2 restart mobile-api            # restart after config change
pm2 stop mobile-api               # stop (will not auto-restart)
pm2 start ecosystem.config.js --env production  # start fresh
pm2 logs mobile-api --lines 50    # recent logs
pm2 monit                         # live resource monitor

Nginx

sudo nginx -t                     # test config before reload
sudo systemctl reload nginx       # reload (zero-downtime)
sudo systemctl restart nginx      # full restart (brief downtime)
sudo systemctl status nginx       # check status
sudo tail -50 /var/log/nginx/error.log  # errors

PostgreSQL

sudo systemctl status postgresql  # check running
sudo -u postgres psql             # open psql as postgres
psql -U postgres -d ufcl_production   # connect to database
sudo tail -50 /var/log/postgresql/postgresql-*.log  # DB logs

Updating the API after a code change

cd /opt/ufcl-api
git pull origin master
cd mobile-api && npm install --production
cd /opt/ufcl-api/mobile-api
pm2 restart mobile-api
pm2 logs mobile-api --lines 20   # verify no startup errors

Running database migrations

cd /opt/ufcl-api
node db/migrate.js
# Always backup before running migrations:
# PGPASSWORD='...' pg_dump -U postgres ufcl_production | gzip > pre-migrate-backup.sql.gz

4. Backup & Restore

Backup schedule

FrequencyRetentionLocation
Daily (02:00)30 days/opt/ufcl-backups/daily/
Weekly (Sunday 03:00)8 weeks/opt/ufcl-backups/weekly/
Monthly (1st 04:00)12 months/opt/ufcl-backups/monthly/

Run a manual backup

PGPASSWORD="your-db-password" bash /opt/ufcl-api/tools/backup.sh
tail -5 /opt/ufcl-backups/backup.log
ls -lh /opt/ufcl-backups/daily/

Restore from backup

# 1. Stop the API
pm2 stop mobile-api

# 2. Drop and recreate the database (DESTRUCTIVE)
psql -U postgres -c "DROP DATABASE ufcl_production;"
psql -U postgres -c "CREATE DATABASE ufcl_production;"
psql -U postgres -c "CREATE EXTENSION IF NOT EXISTS pgcrypto;" ufcl_production

# 3. Restore from the chosen backup file
BACKUP_FILE="/opt/ufcl-backups/daily/ufcl-20260629_020001.sql.gz"
gunzip -c "$BACKUP_FILE" | psql -U postgres -d ufcl_production

# 4. Restart the API
pm2 start mobile-api
Step 2 is irreversible. Confirm the backup file is readable before dropping the database: gunzip -t "$BACKUP_FILE" && echo "OK"

Verify a backup is readable

gunzip -t /opt/ufcl-backups/daily/ufcl-20260629_020001.sql.gz && echo "Backup is valid"

5. Monitoring

Dashboard

Open https://192.168.1.5/dashboard.html in a browser. Enter the server URL (https://192.168.1.5) and the METRICS_TOKEN from .env. The dashboard auto-refreshes every 30 seconds. It shows:

  • Uptime, active sessions, total requests
  • Response time (average and p95)
  • Heap memory used
  • Database latency
  • Auth failure count, rate limit hits
  • Last 10 slow requests (>500 ms)
  • Current APK version

Health check endpoints

# Liveness — API is running
curl -k https://192.168.1.5/api/health

# Readiness — database is reachable
curl -k https://192.168.1.5/api/ready

# Metrics — token required
curl -k -H "Authorization: Bearer $METRICS_TOKEN" https://192.168.1.5/api/metrics | jq .

6. APK Build & Distribution

Building the release APK

cd /path/to/repo/mobile/android

# Set version (increment versionCode each release)
export VERSION_CODE=2
export VERSION_NAME=1.0.1

./gradlew assembleRelease

# Output: app/build/outputs/apk/release/app-release.apk
# Must be signed with the UFCL release keystore
The release keystore file must be kept secure. If the keystore is lost, the APK cannot be updated (Android will refuse to install a new APK signed with a different key over the old one). Store the keystore in archive/v1.0.0/ and in a secure offline location.

Deploying a new APK to the server

# Copy new APK to the downloads directory
sudo cp app-release-v1.0.1.apk /opt/ufcl-api/public/downloads/UFCL-production.apk

# Update version.json
echo '{"version":"1.0.1","versionCode":2}' \
  | sudo tee /opt/ufcl-api/public/downloads/version.json

# Verify download endpoint
curl -kI https://192.168.1.5/downloads/UFCL-production.apk

Installing on Android devices

  1. On the device: Settings → Security → Allow unknown sources (or "Install unknown apps" for the browser)
  2. Open the device browser → navigate to https://192.168.1.5/downloads/UFCL-production.apk
  3. Download and install. Accept the TLS warning (self-signed certificate).
  4. Alternatively: generate a QR code for the APK URL using any QR generator and display it on a notice board.

Distribute the TLS certificate to devices

# The certificate file for device installation:
/etc/ssl/ufcl/server.crt

# Transfer to device via USB or LAN file share, then:
# Android Settings → Security → Install a certificate → CA Certificate → select server.crt

Useful log commands

# All error-level events today
grep '"level":"error"' /opt/ufcl-api/logs/app-$(date +%Y-%m-%d).log | jq .

# All login failures in the last hour
grep '"event":"login_failed"' /opt/ufcl-api/logs/app-$(date +%Y-%m-%d).log | tail -20

# Slow requests
grep '"duration_ms"' /opt/ufcl-api/logs/app-$(date +%Y-%m-%d).log \
  | jq 'select(.duration_ms > 500)' | head -20

# Live tail
tail -f /opt/ufcl-api/logs/app-$(date +%Y-%m-%d).log | jq .

Audit log (database)

# All logins today
psql -U postgres -d ufcl_production -c \
  "SELECT username, role, event, ip, created_at
   FROM audit_log
   WHERE created_at::date = CURRENT_DATE
   ORDER BY created_at DESC LIMIT 50;"

# Failed logins in last 24 hours
psql -U postgres -d ufcl_production -c \
  "SELECT username, ip, created_at FROM audit_log
   WHERE event = 'login_failed'
   AND created_at > NOW() - INTERVAL '24 hours'
   ORDER BY created_at DESC;"

10. Disaster Recovery

Scenario: API is down (PM2 crashed)
pm2 status
pm2 logs mobile-api --lines 50   # find the error
pm2 start mobile-api              # restart
pm2 save

If PM2 itself is not running: pm2 resurrect

Scenario: Server rebooted (after power cut)

If PM2 startup was configured (pm2 startup && pm2 save), the API restarts automatically. Verify: pm2 status. If not running: pm2 resurrect then pm2 status.

Verify Nginx: sudo systemctl status nginx. Should be "active (running)".

Verify PostgreSQL: sudo systemctl status postgresql. Should be "active (running)".

Scenario: Database corrupted or deleted
  1. Stop API: pm2 stop mobile-api
  2. Find the most recent valid backup: ls -lt /opt/ufcl-backups/daily/ | head -5
  3. Verify it: gunzip -t /opt/ufcl-backups/daily/ufcl-<timestamp>.sql.gz
  4. Recreate DB: psql -U postgres -c "DROP DATABASE IF EXISTS ufcl_production; CREATE DATABASE ufcl_production;"
  5. Restore: gunzip -c /opt/ufcl-backups/daily/ufcl-<timestamp>.sql.gz | psql -U postgres -d ufcl_production
  6. Start API: pm2 start mobile-api
  7. Verify: curl -k https://192.168.1.5/api/ready | jq '{ok, db}'
Any data entered after the backup timestamp will be lost. Inform users of the data gap.
Scenario: TLS certificate expired
# Check expiry
openssl x509 -in /etc/ssl/ufcl/server.crt -noout -dates

# Renew (re-run the setup script)
sudo bash /opt/ufcl-api/tools/ssl-setup.sh
sudo systemctl reload nginx

# Re-distribute the new server.crt to all Android devices
Scenario: Disk full
df -h /                      # check disk usage
du -sh /opt/ufcl-backups/*   # check backup size
du -sh /opt/ufcl-api/logs/*  # check log size

# Emergency: force logrotate to free space now
sudo logrotate -f /etc/logrotate.d/ufcl

# Remove backups older than 35 days if still low on disk
find /opt/ufcl-backups/daily -mtime +35 -name "*.sql.gz" -delete
Rollback to a previous APK version

Previous APKs are stored in archive/vX.Y.Z/apk/. To roll back:

sudo cp archive/v1.0.0/apk/UFCL-mobile-v1.0.0.apk \
     /opt/ufcl-api/public/downloads/UFCL-production.apk
echo '{"version":"1.0.0","versionCode":1}' \
  | sudo tee /opt/ufcl-api/public/downloads/version.json

Users with the newer version installed will need to uninstall and reinstall the older APK manually (Android does not allow downgrading in-place).
