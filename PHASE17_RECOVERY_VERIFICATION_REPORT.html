2. Scenario Details

DR-01 — API Process Crash
RTO: < 30 seconds
Data loss: None
Auto-recovery: Yes

Mechanism: PM2 monitors the process. On unexpected exit, PM2 respawns immediately. Config: max_restarts: 10, min_uptime: 30s.

If process crashes 10 times in rapid succession (e.g. fatal startup error), PM2 stops restarting and logs the failure. This prevents crash-loop resource exhaustion.

Verification

# Kill the API process unexpectedly
kill -9 $(pm2 pid mobile-api)

# Wait 5 seconds
pm2 status
# Expected: mobile-api status = online, restarts incremented by 1

curl -k https://192.168.1.5/api/health | jq .ok
# Expected: true
DR-02 — Memory Limit Exceeded
RTO: < 30 seconds
Data loss: In-flight request only
Auto-recovery: Yes

Mechanism: PM2 max_memory_restart: 512M. When heap exceeds 512 MB, PM2 sends SIGTERM (graceful shutdown) then respawns.

Graceful shutdown: Server handles SIGTERM — closes DB pool, finishes in-flight requests, exits cleanly within 10 seconds.

# Monitor memory
pm2 monit
# In a separate terminal, watch memory:
watch -n 2 "pm2 list | grep mobile-api"
DR-03 — Server Reboot / Power Loss
RTO: < 2 minutes (boot time)
Data loss: None (PostgreSQL WAL)
Auto-recovery: Yes

Mechanism: PM2 startup hook registers a systemd service that starts PM2 on boot. nginx and PostgreSQL use systemctl enable to auto-start. UFW rules persist across reboots.

Verification

sudo reboot
# After boot (~60 seconds):
systemctl status nginx        # should show: active (running)
systemctl status postgresql   # should show: active (running)
pm2 status                   # should show: mobile-api online
curl -k https://192.168.1.5/api/ready | jq .ok   # true
curl -k https://192.168.1.5/version.json | jq .version  # "1.0.0"

IT must execute this test before go-live sign-off.

DR-04 — Database Corruption / Data Loss
RTO: < 30 minutes
Data loss: Up to 24 hours (since last daily backup)
Auto-recovery: No — manual procedure

Detection signals

  • curl -k https://192.168.1.5/api/ready returns {"ok":false,"db":{"connected":false}}
  • PM2 logs: error: DB connection failed
  • Users see "Server error" on all screens

Recovery procedure

# 1. Stop API
pm2 stop mobile-api

# 2. Find latest good backup
ls -lt /opt/ufcl-backups/daily/ | head -5
BACKUP_DATE=2026-06-29   # use actual date

# 3. Drop and recreate DB
sudo -u postgres psql -c "DROP DATABASE IF EXISTS ufcl_production;"
sudo -u postgres psql -c "CREATE DATABASE ufcl_production;"

# 4. Restore
gunzip -c /opt/ufcl-backups/daily/db-${BACKUP_DATE}.sql.gz \
  | sudo -u postgres psql -d ufcl_production

# 5. Verify row counts
sudo -u postgres psql -d ufcl_production -c \
  "SELECT tablename, n_live_tup FROM pg_stat_user_tables ORDER BY n_live_tup DESC;"

# 6. Restart and verify
pm2 start ecosystem.config.js --env production
curl -k https://192.168.1.5/api/ready | jq .
# Expected: { "ok": true, "db": { "connected": true } }

DR-06 — Lost / Stolen Device
RTO: < 5 minutes
Data loss: None
Auto-recovery: No — admin action required

Procedure

# Deactivate the user account
sudo -u postgres psql -d ufcl_production -c \
  "UPDATE app_users SET active = false WHERE username = 'john.doe';"

# Verification: user's next API call will return 403 "Account is deactivated"
# Any existing JWT becomes functionally useless because /api/auth/me returns 403
# The user is navigated to login screen on next token revalidation

Note: Since JWT is stateless and 8-hour expiry is fixed, there is a maximum 8-hour window during which the stolen JWT could be used if active = false does not invalidate existing tokens mid-session. Mitigation: deactivate immediately; advise department head to monitor audit_log for any activity from that username after deactivation.

DR-07 — Full Server Hardware Failure
RTO: < 4 hours
Data loss: Up to 24 hours
Auto-recovery: No — full rebuild required

Procedure summary

  1. Provision new Ubuntu 20.04+ server with same LAN IP (192.168.1.5)
  2. Install: nodejs (v22), postgresql (v14+), nginx, pm2
  3. Clone the repository to /opt/ufcl-api
  4. Restore .env from backup: tar -xzf config-YYYY-MM-DD.tar.gz -C /
  5. Run cd mobile-api && npm ci
  6. Restore database from latest backup
  7. Run bash tools/ssl-setup.sh, bash tools/firewall-setup.sh
  8. Copy tools/nginx.conf to /etc/nginx/sites-available/ufcl, test, enable
  9. Run pm2 start ecosystem.config.js --env production && pm2 save && pm2 startup
  10. Run bash tools/cron-setup.sh
  11. Restore APK: tar -xzf updates-YYYY-MM-DD.tar.gz -C /opt/ufcl-api/updates/
  12. Verify: curl -k https://192.168.1.5/api/ready | jq .ok
